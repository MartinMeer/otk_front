### 3) Generate sitemap.xml during deploy and update robots.txt
- **Tips**
    - Don’t update sitemap.xml by hand. Automate it.
    - Only include URLs that return 200 and are indexable.
    - lastmod is useful; changefreq/priority are optional.
    - Keep URL format (with/without trailing slash) consistent.    
    - Keep “under construction” pages out of the sitemap and add a meta robots noindex on those pages.
    - How to automate: Build-time (recommended):
        - Keep a small routes manifest (path, indexable, lastmod).
        - Use a Node script with the “sitemap” package to generate public/sitemap.xml during your build.
        - Wire it into your build command (CRA/Vite) so CI runs it on every deploy.
    
    - Under-construction handling
        - Exclude from sitemap
        - Add <meta name="robots" content="noindex, nofollow"> on those pages (e.g., via react-helmet-async).

    - Robots and search consoles:
        - public/robots.txt should include: Sitemap: https://your-domain/sitemap.xml
        - Submit the sitemap once in Google Search Console and Bing; they’ll refetch it after deploys.    
    For reference, use /doc/seo/seo-undeveloped-pages-tips.md

- **Action**:
  - In `scripts/deploy.mjs`, after build, write `dist/sitemap.xml` using logic from `src/utils/sitemapGenerator.ts` with `SITE_BASE_URL` env.
  - Update `public/robots.txt` to: `Sitemap: https://<your-domain>/sitemap.xml` (replace placeholder).
- **Acceptance**: `dist/sitemap.xml` exists/valid; robots points to real URL; Search Console accepts sitemap.

### 4) Make essential PWA tags static
- **Action (index.html)**: add
  - `<link rel="manifest" href="/site.webmanifest">`
  - `<meta name="theme-color" content="#1e40af">`
- Keep runtime `FaviconTags` if desired, but static tags improve detection.
- **Acceptance**: Lighthouse PWA audit detects manifest/theme color without JS.

### 5) De-duplicate Service Worker registration
- **Action**: Keep SW registration in one place (prefer `index.html` for earliest registration). Remove `registerServiceWorker()` from `src/App.tsx` and its `useEffect` call.
- **Acceptance**: Single SW registration in console; scope remains `/`.

### 6) Use clean canonical URLs (no hash)
- **Action (src/components/SEO/SEOMetaTags.tsx)**:
  - Default `canonicalUrl` to `window.location.origin + window.location.pathname`.
  - Optionally pass a stable canonical from `App.tsx` per logical page (hash router still canonicalizes to `/`).
- **Acceptance**: Source shows one canonical without a `#` fragment.

### 7) Footer contact and legal
- **Action (src/components/Layout/Footer.tsx)**:
  - Replace `email@example.com` with the real contact.
  - Add links to Privacy Policy and Cookie Policy (static pages in `public/` or external URLs).
- **Acceptance**: Users see valid contact/policy links.

### 8) Hosting cache headers
- **If Netlify**: `dist/_headers` is generated by `npm run deploy` and will apply.
- **If NGINX/Cloudflare/S3+CF**: replicate rules:
  - `main.js`, `main.css`, `images/*`: `Cache-Control: public, max-age=31536000, immutable`
  - `version.json`, `deployment.json`, `sw.js`: `Cache-Control: no-cache, no-store, must-revalidate`
- **Acceptance**: Headers confirmed in DevTools > Network.

### 9) Verify API CORS for production origin
- **Action**: Ensure `https://api.otk-help.martinmeer.com` allows your prod origin.
  - Test with: `curl -i -X OPTIONS https://api.otk-help.martinmeer.com/ost22 -H "Origin: https://<your-domain>" -H "Access-Control-Request-Method: POST"`
- **Acceptance**: Browser requests to all endpoints succeed without CORS errors.

### 10) Optional cleanups
- Guard or remove dev-only `src/components/Dev/SEODev.tsx` in production.
- In `tsconfig.json`, remove `".next/types/**/*.ts"` include (leftover from Next.js).
- Consider adding `404.html` -> `index.html` fallback (harmless with hash routing).

### 11) Rebuild, smoke test, deploy
- **Commands**:
  - `npm run build`
  - `npm run deploy` (creates `dist/_headers`, `version.json`, `deployment.json`, and should write `sitemap.xml` after you wire it)
  - Local preview: `npx serve dist -p 8001`
- **Manual checks**:
  - Navigate: Home, `#ost22`, `#esdp`; no console errors.
  - Meta: Title/description/canonical present; OG/Twitter tags populated; preview tools ok.
  - PWA: SW installed; offline for cached assets; `version.json` reachable.
  - API: Calculations return results; no CORS issues.
  - Caching: Headers as intended.
